## 一、技术栈选型

### 1.3 选型理由

- **FastAPI**：高性能异步框架，原生支持 WebSocket，自动生成 OpenAPI 文档，适合 AI 应用场景。
- **SQLite**：测试环境零配置，单文件部署，满足 10-30 人并发测试需求；后续可平滑迁移至 PostgreSQL。
- **Vue 3 + Element Plus**：用户偏好技术栈，组件丰富，开发效率高，响应式设计适配移动端浏览器。
- **scikit-learn TF-IDF**：RAG 向量化方案，无需下载大模型，离线可用，中文支持良好（字符级 n-gram）；生产环境可升级为神经向量模型。
- **OpenAI 兼容接口**：LLM 调用层抽象，可对接 OpenAI / DeepSeek / 智谱 / 通义千问等任意兼容服务商，通过环境变量切换。

## 五、核心技术方案

### 5.1 实时聊天（WebSocket）

- 客户端通过 `ws://host/ws/chat/{jwt_token}` 建立连接
- 服务端验证 token，将连接按 couple_id 分组管理
- 消息流程：客户端发送 → 服务端持久化 → 推送至对方在线连接 → 返回确认
- 离线消息存入数据库，对方上线后拉取
- 已读/未读状态通过 WebSocket 实时同步

### 5.2 AI 服务封装

```python
class AIService:
    """统一 LLM 调用层，兼容 OpenAI 接口"""
    # 通过 .env 配置：API_KEY, API_BASE, MODEL_NAME
    # 无 API_KEY 时回退至规则模板响应（保证测试可用）
```

- 多轮对话：保留 conversation 上下文（最近 10 轮），按 token 截断
- 日记总结：聚合指定时间段日记内容，调用 LLM 提取关键事件与情绪倾向
- 内容生成：根据场景模板 + 用户关键词生成文案

### 5.3 RAG 检索引擎

```
文档上传 → 文本提取 → 递归切片（500字/片，100字重叠）
    → TF-IDF 向量化（字符 1-2 gram，中英文兼容）
    → 存入 document_chunks 表

用户提问 → TF-IDF 向量化 → 余弦相似度 Top-K 检索
    → 拼接上下文 + 原始问题 → LLM 生成回答
    → 返回回答 + 来源切片（可溯源）
```

- 向量持久化：Base64 编码存入 SQLite，启动时加载至内存
- 数据隔离：按 couple_id 隔离知识库，仅情侣双方可访问

### 5.4 认证与安全

- JWT 令牌：有效期 7 天，WebSocket 与 REST 共用
- 密码存储：bcrypt 哈希
- 验证码：测试环境接口直接返回验证码（不实际发短信），5 分钟过期
- 情侣数据隔离：所有情侣模块接口校验 couple_id 归属

## 七、性能与可扩展性

| 指标 | 目标 | 方案 |
|------|------|------|
| 基础功能响应 | ≤2s | SQLite 本地访问 + 异步 IO |
| AI 功能响应 | ≤5s | LLM 流式返回 + 超时控制 |
| 并发支持 | 10-30人 | Uvicorn 多 worker + WebSocket 连接池 |
| 可扩展性 | AI 迭代 | AI 服务层抽象，新增功能仅需实现 service |
| 数据库迁移 | SQLite→PostgreSQL | SQLAlchemy ORM 隔离，切换连接串即可 |
