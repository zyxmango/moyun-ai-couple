# 情侣互动 APP（含 AI 应用功能）项目设计文档

> 本文档由《项目说明文档》与《技术说明文档》合并而成，涵盖功能需求、技术架构、数据库设计、接口设计、核心逻辑与部署方案，作为开发与交付的统一依据。

---

## 第一章 项目概述

### 1.1 项目定位

本项目开发一款面向情侣的私密互动 APP，核心定位为"**情感陪伴 + AI 赋能**"，兼顾基础情侣互动功能与 AI 智能服务。仅用于内部测试、流程验证，暂不上线应用商店、不对外公开推广。

项目需实现客户端（移动端浏览器跨端访问）与后端服务的完整联动，确保功能流畅、逻辑闭环，同时为后续 AI 功能迭代预留扩展空间。

### 1.2 适用范围

- 测试环境：本地电脑 / 轻量云服务器部署
- 无需合规资质（软著、ICP 备案、苹果开发者账号等）
- 支持 10-30 人同时在线测试

## 第二章 功能需求

### 2.1 基础情侣互动功能（必做）

#### 2.1.1 用户体系
- 手机号注册/登录（测试环境跳过短信验证，后台手动生成验证码）
- 情侣绑定（通过唯一配对码或账号关联）
- 账号信息修改（昵称、头像、情侣关系状态）

#### 2.1.2 私密聊天
- 一对一实时文字聊天
- 图片发送
- 消息已读/未读状态显示
- 聊天记录本地存储与云端同步（测试阶段简化存储逻辑）
- 保证聊天无延迟、无丢包

#### 2.1.3 情侣专属模块
- **纪念日记录与提醒**：自定义纪念日、到期推送提醒
- **共享相册**：图片上传、查看、删除，仅情侣双方可见
- **情侣日记**：双方可共同编辑、查看，支持文字+图片混合记录

#### 2.1.4 基础设置
- 消息通知开关
- 账号退出登录
- 情侣关系解除（解除后双方数据保留但无法再互动）

### 2.2 AI 应用功能（核心亮点，必做）

#### 2.2.1 AI 情感陪伴
- 基于大模型 API 实现，支持情侣双方单独与 AI 对话
- 提供情感倾诉、情绪安抚、恋爱建议等服务
- 对话上下文保留，支持多轮交互

#### 2.2.2 AI 内容生成
- 根据情侣纪念日、日常互动场景，自动生成专属文案（纪念日祝福、约会方案）
- 支持用户输入关键词，AI 生成个性化内容

#### 2.2.3 AI 日记总结
- 自动提取情侣日记中的关键内容、情绪倾向
- 生成每日/每周情感总结报告
- 支持报告查看与分享（仅情侣双方可见）

#### 2.2.4 AI 智能提醒
- 结合情侣互动数据与纪念日信息，智能推送个性化提醒
- 示例："距离你们的恋爱纪念日还有3天，是否需要准备惊喜？"

#### 2.2.5 对话式 RAG 智能旅游记录智能体
- 以对话交互为核心，支持情侣双方上传自定义文档（旅游日记、旅行攻略、行程记录等）
- 上传后自动完成文档切片、向量化处理并存入专属知识库
- 用户通过自然语言对话与智能体交互，无需手动输入关键词检索
- 智能体理解对话意图，自动调取知识库中的旅游相关内容并以对话形式回复
- 回复内容关联原文来源，确保信息可溯源

### 2.3 后台管理
- 查看用户数据
- 查看情侣绑定状态
- 查看 AI 功能调用日志
- 便于测试排查问题

## 第三章 非功能需求与验收标准

### 3.1 性能要求
- 基础功能响应时间 ≤ 2 秒
- AI 功能响应时间 ≤ 5 秒（大模型 API 调用延迟除外）

### 3.3 可扩展性

### 3.4 验收标准
- 所有核心功能（基础情侣互动 + AI 应用）正常运行，无明显 bug
- 客户端与后端联动流畅，接口调用正常，数据同步无延迟
- 可本地部署与测试
- 提供项目源码、部署文档、测试报告、项目说明文档

## 第四章 技术架构

### 4.1 技术栈

**后端：** Python 3.10 + FastAPI + SQLAlchemy + SQLite + WebSocket + scikit-learn（RAG 向量化）+ OpenAI 兼容 LLM 接口

**前端：** Vue 3 + Element Plus + Vue Router + Pinia + Axios + Vite（墨韵精炼设计风格）

**环境管理：** conda 虚拟环境（环境名：couple-app-ai）

### 4.2 选型理由
- **FastAPI**：高性能异步框架，原生支持 WebSocket，自动生成 OpenAPI 文档。
- **SQLite**：测试环境零配置，单文件部署，满足并发测试需求。
- **Vue 3 + Element Plus**：组件丰富，开发效率高，响应式设计适配移动端。
- **scikit-learn TF-IDF**：RAG 向量化无需下载大模型，离线可用，中文兼容好。
- **OpenAI 兼容接口**：LLM 调用层抽象，可对接任意兼容服务商。

## 第五章 数据库设计

数据库采用 SQLite（测试环境），通过 SQLAlchemy ORM 操作，共 11 张表：

### 5.1 ER 关系概览

```
users ──┐
        ├─< couples >── users
        │
        ├─< messages（聊天消息）
        ├─< anniversaries（纪念日）
        ├─< photos（相册）
        ├─< diaries（日记）
        ├─< ai_conversations ─< ai_messages（AI 对话）
        ├─< documents ─< document_chunks（RAG 文档）
        └─< ai_call_logs（AI 调用日志）

verification_codes（验证码，独立）
reminders（提醒，关联 couples）
```

### 5.2 核心数据表

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| users | 用户 | phone, password_hash, nickname, avatar, couple_id, is_admin, notify_enabled |
| couples | 情侣关系 | pairing_code, user1_id, user2_id, status(pending/active/dissolved) |
| verification_codes | 验证码 | phone, code, expires_at, used |
| messages | 聊天消息 | couple_id, sender_id, content, msg_type, read_status |
| anniversaries | 纪念日 | couple_id, title, date, reminder_enabled |
| photos | 相册 | couple_id, uploader_id, filename, file_path |
| diaries | 情侣日记 | couple_id, author_id, title, content, mood |
| ai_conversations | AI 对话 | user_id, conv_type, title, context |
| ai_messages | AI 消息 | conversation_id, role, content, sources |
| documents | RAG 文档 | couple_id, filename, content, chunk_count |
| document_chunks | 文档切片 | document_id, couple_id, chunk_index, content, vector_b64 |
| reminders | 提醒 | couple_id, reminder_type, content, trigger_date, is_sent |
| ai_call_logs | AI 调用日志 | user_id, feature, input_text, output_text, status |

## 第七章 核心逻辑设计

### 7.1 实时聊天（WebSocket）
- 客户端通过 `ws://host/ws/chat/{jwt_token}` 建立连接
- 服务端验证 token，按 couple_id 分组管理连接
- 消息流程：客户端发送 → 服务端持久化 → 推送至对方在线连接 → 返回确认
- 离线消息存入数据库，对方上线后拉取
- 已读/未读状态通过 WebSocket 实时同步

### 7.2 AI 服务封装
- 统一 LLM 调用层，兼容 OpenAI 接口，通过 .env 配置 API_KEY / API_BASE / MODEL_NAME
- 无 API_KEY 时回退至规则模板响应（保证测试可用）
- 多轮对话：保留最近 10 轮上下文
- 日记总结：聚合日记内容，LLM 提取关键事件与情绪倾向
- 内容生成：场景模板 + 用户关键词生成文案

### 7.3 RAG 检索引擎

```
文档上传 → 文本提取 → 递归切片（500字/片，100字重叠）
    → TF-IDF 向量化（字符 1-2 gram，中英文兼容）
    → 存入 document_chunks 表

用户提问 → TF-IDF 向量化 → 余弦相似度 Top-K 检索
    → 拼接上下文 + 原始问题 → LLM 生成回答
    → 返回回答 + 来源切片（可溯源）
```

- 向量持久化：Base64 编码存入 SQLite，启动时加载至内存
- 数据隔离：按 couple_id 隔离知识库，仅情侣双方可访问

### 7.4 认证与安全
- JWT 令牌：有效期 7 天，WebSocket 与 REST 共用
- 密码存储：bcrypt 哈希
- 验证码：测试环境接口直接返回，5 分钟过期
- 情侣数据隔离：所有情侣模块接口校验 couple_id 归属

### 7.5 情侣绑定流程
1. 用户 A 注册后调用生成配对码 → 获得 6 位唯一配对码
2. 用户 B 注册后输入配对码 → 调用绑定接口
3. 服务端校验配对码有效性，建立情侣关系（status=active）
4. 双方 couple_id 关联，可开始互动

## 第八章 部署方案

### 8.1 本地开发部署

**后端：**
```bash
conda create -n couple-app-ai python=3.10 -y
conda activate couple-app-ai
cd backend && pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

**前端：**
```bash
cd frontend && npm install
npm run dev
```

### 8.2 环境配置（.env）
```
SECRET_KEY=your-secret-key
DATABASE_URL=sqlite:///./data/couple_app.db
AI_API_KEY=          # 留空则使用规则模板响应
AI_API_BASE=https://api.openai.com/v1
AI_MODEL=gpt-4o-mini
ADMIN_PHONE=13800000000   # 首次注册此手机号自动成为管理员
```

### 8.3 Docker 部署（预留）
后端 Dockerfile + 前端构建静态文件 → Nginx 反代，支持一键部署。

## 第九章 性能与可扩展性

| 指标 | 目标 | 方案 |
|------|------|------|
| 基础功能响应 | ≤2s | SQLite 本地访问 + 异步 IO |
